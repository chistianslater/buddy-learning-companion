# App Flow Document for "Der Digitale Lernbegleiter"

## Onboarding and Sign-In/Sign-Up
A new user lands on a simple welcome page that explains the purpose of Der Digitale Lernbegleiter and invites them to sign up or log in. Clicking the sign-up button opens a Clerk-powered modal where users can choose to register with an email address and password or use a social login option like Google or Apple. After entering their credentials and verifying their email through a one-time code, the user is guided to complete a short setup form. In this form the guardian enters their personal details and then adds a learner profile by providing the child’s name and selecting initial learning interests from a calm, low-stimulus list. Once this initial setup is complete, the user is taken directly into the application. From any page they can sign out using a link in the top navigation bar, and if they forget their password they can click a “Forgot Password” link to receive a reset email and set a new password.

## Main Dashboard or Home Page
After logging in, the user sees a clean header with the application logo on the left and profile controls on the right. Beneath the header is a simple navigation menu that lets them switch between the learner’s Chat interface, the guardian’s Subscription status page, and the Settings area. Learners enter directly into a text-first chat window where they interact with their Buddy, and guardians landing on this view can click the “Switch to Guardian View” option to see subscription details. The default learner view features a calm background, the conversation history in a single scrollable column, and a text input field at the bottom. From this main page the user can click on the profile icon to access the account menu or use the navigation links to move to other pages.

## Detailed Feature Flows and Page Transitions
When a learner types a message and sends it, the chat window remains in place while a small spinner appears next to the Buddy’s avatar. A server action runs behind the scenes, fetching the learner’s interests and competency data from the Supabase database, building a prompt in the OpenAI utility, and then streaming the AI response back into the conversation. The Buddy’s reply appears word by word in the chat area without causing any page refresh. If the learner asks a follow-up question, the same process repeats seamlessly. Guardians can click the navigation link for Subscription status to see their current plan, next billing date, and a button to manage payment details. Clicking this button takes them to a Stripe checkout page embedded in the app, where they can enter card information, review the charges in a calm interface, and confirm the subscription. Closing the checkout returns them to the Subscription page, which refreshes automatically to show the updated status. Both learners and guardians can go to the profile icon and choose “Edit Profile” to land on a page where they can update names, contact email, or learner interests. Saving these changes triggers a server action that writes the new data to Supabase and then navigates them back to their previous view.

## Settings and Account Management
From the main navigation, users can select Settings to open a page with sections for Personal Information, Notification Preferences, and Security. In Personal Information they see editable fields for name and email, and clicking save updates the database and shows a brief confirmation message. In Notification Preferences they can toggle email reminders on or off, and changes are applied instantly without leaving the page. The Security section offers a “Change Password” button that opens another Clerk modal to enter the current password and set a new one. If the user has an active subscription, a Billing section appears below these settings, showing the plan name, renewal date, and a link to update payment details or cancel the subscription. After making any updates in Settings, users can click “Back to Chat” or “Back to Subscription” at the top of the page to return to their main workflow.

## Error States and Alternate Paths
If a user enters an invalid email or password during sign-in, a clear error message appears above the form explaining that their credentials are incorrect and suggesting they retry or reset their password. When starting the password recovery flow, entering an unregistered email triggers a gentle warning that no account was found, while entering a valid email sends the reset link and displays a confirmation message. During chat, if the OpenAI API call fails or network connectivity is lost, the user sees a friendly message from the Buddy apologizing for the interruption and suggesting they check their connection or try again later. In the Subscription area, if a credit card is declined or the Stripe checkout fails, the app displays the specific error from Stripe and offers a link to update payment details. Any time the user encounters an error, the app provides a visible button to retry the last action or return to the safe home view without losing their existing data.

## Conclusion and Overall App Journey
A typical user journey begins when a guardian signs up on the landing page, verifies their email, and sets up a learner profile by selecting interests. From there, the learner logs in to a calm chat interface where they engage with their Buddy through guided, scaffolded questions. Behind the scenes, every conversation triggers secure server-side logic that fetches competency data and updates progress without pressuring the learner. Guardians can manage their subscription and payment methods in a dedicated section, and both roles can update personal details in the Settings area. If at any point something goes wrong, clear and reassuring error messages guide the user back to a functional flow. Day after day, learners return to the chat to explore new topics in a pressure-free environment, while guardians rest assured that billing, data privacy, and account management are handled smoothly and securely.
